🎯 KYA BANAYA
--------------
LangGraph agent jo LinkedIn post likhta hai, khud web search karta hai
(Tavily), human se review leta hai (approve/reject+feedback loop), aur
FastAPI + React ke through poora web app bana hua hai. Approved posts
MongoDB me permanently save hote hain.


┌──────────────────────────────────────────────────────────────┐
│  1️⃣  AGENT LOGIC (LangGraph) — agent.py                      │
└──────────────────────────────────────────────────────────────┘

FLOW DIAGRAM:

   START
     │
     ▼
 ┌─────────┐   feedback + topic
 │ WRITER  │◄──────────────────────┐
 │ (agent) │                       │
 └────┬────┘                       │
      │ draft ban gaya             │
      ▼                            │
 ┌──────────────┐   ❌ rejected    │
 │ HUMAN_REVIEW │───────────────────┘
 │ (interrupt!) │
 └──────┬───────┘
        │ ✅ approved  OR  attempt >= 5
        ▼
       END

🔑 KEY CONCEPTS:
  • State (dict)     → topic, draft, review_feedback, is_approved, attempt
                       — poore graph me pass hoti rehti hai
  • writer_agent     → create_react_agent() se bana — khud decide karta
                       hai search karni hai ya nahi (Tavily tool)
  • interrupt()      → graph ko PAUSE karta hai human_review node pe,
                       jab tak resume na ho aage nahi badhta
  • checkpointer     → thread_id ke against graph ki state yaad rakhta
                       hai (MemorySaver = RAM only, restart pe gayab)

┌──────────────────────────────────────────────────────────────┐
│  3️⃣  API ENDPOINTS + SSE STREAMING                            │
└──────────────────────────────────────────────────────────────┘

  POST /api/generate  { topic }
       → naya thread_id banta hai, graph start hota hai
       → SSE stream: status → status → awaiting_review

  POST /api/review  { thread_id, response: "approved" / feedback }
       → same thread_id pe graph RESUME hota hai (Command(resume=...))
       → agar approved → MongoDB me save + "done" event
       → agar reject → naya draft → wapas "awaiting_review"

  GET  /api/posts
       → saare approved posts ki history (MongoDB se)

  SSE EVENT TYPES (React inhe parse karta hai):
    "status"           → { message, node }        "Writer likh raha hai..."
    "awaiting_review"  → { thread_id, draft, attempt }
    "done"             → { draft, approved, attempt }

🎯 KYA ADD HUA
--------------
Poore app ko login-protected banaya. Ab koi bhi bina account ke
generate/review/posts use nahi kar sakta. Har user apna alag account
rakhta hai (password hashed, kabhi plain text save nahi hota).


┌──────────────────────────────────────────────────────────────┐
│  1️⃣  JWT FLOW — pura concept ek nazar mein                    │
└──────────────────────────────────────────────────────────────┘

  SIGNUP:
    User email+password bharta hai
          │
          ▼
    Backend password ko HASH karta hai (bcrypt) — original
    password kabhi save nahi hota, sirf uska hash
          │
          ▼
    MongoDB "users" collection me save: { email, hashed_password }


  LOGIN:
    User email+password bharta hai
          │
          ▼
    Backend DB se user dhoondta hai, password verify karta hai
    (hash se compare — verify_password())
          │
          ▼
    ✅ match ho gaya → JWT TOKEN banta hai (create_access_token)
       Token ke andar: { "sub": email, "exp": expiry_time }
          │
          ▼
    Token React ko wapas milta hai → localStorage me save hota hai


  PROTECTED REQUEST (generate/review/posts):
    React fetch call ke header me token bhejta hai:
       "Authorization: Bearer <token>"
          │
          ▼
    Backend ka get_current_user() dependency token verify karta hai
    (decode_access_token) — invalid/expired → 401 error, request reject
          │
          ▼
    ✅ valid → route ka actual code chalta hai
